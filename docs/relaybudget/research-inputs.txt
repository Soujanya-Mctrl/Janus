SHEET Continuity Guide
A1=Topic | B1=Explanation
A2=Meaning | B2=Continuity is a track for building on a project/codebase that existed before the hackathon, instead of claiming all project-specific work was started from scratch at kickoff.
A3=Who can enter | B3=Only teams/projects that meet the specific event and sponsor eligibility rules. A prior project by itself does not automatically make every continuity bounty available.
A4=Allowed work | B4=Substantive new functionality, meaningful integration, production hardening, architecture changes or a real feature shipped during the event. Some sponsor tracks permit rebuilding an existing product if the new sponsor integration is real.
A5=Not enough | B5=Cosmetic UI polish, bug fixes alone where the bounty asks for substantive work, repackaging an old demo, or presenting old functionality as newly built.
A6=Evidence to prepare | B6=Dated pre-event commit or prior submission link; commit history throughout event; changelog with dated work; README section separating old work from new work; short demo focused on the new functionality; sponsor-specific transaction/request IDs.
A7=Disclosure | B7=ETHGlobal rules say pre-existing work must be disclosed in writing and included in the submission. All new extension work must remain open source for Continuity submissions.
A8=Classic vs Continuity | B8=Classic/from-scratch track requires project-specific code/design/assets to begin when hacking officially starts. If not in an approved Continuity track, pre-existing project-specific work can make partner-prize/finalist submissions ineligible.
A9=Sponsor-specific caveat | B9=Check each bounty. Continuity eligibility differs by sponsor; some sponsors have a dedicated continuity bounty, others do not. Do not assume a continuity project can enter every track.
A10=Risk | B10=Undisclosed pre-existing work or misrepresenting what was built during the event can lead to disqualification, prize revocation or a ban from future events.
A11=Official source | B11=https://ethglobal.com/rules

SHEET Continuity Guide
A1=Topic | B1=Explanation
A2=Meaning | B2=Continuity is a track for building on a project/codebase that existed before the hackathon, instead of claiming all project-specific work was started from scratch at kickoff.
A3=Who can enter | B3=Only teams/projects that meet the specific event and sponsor eligibility rules. A prior project by itself does not automatically make every continuity bounty available.
A4=Allowed work | B4=Substantive new functionality, meaningful integration, production hardening, architecture changes or a real feature shipped during the event. Some sponsor tracks permit rebuilding an existing product if the new sponsor integration is real.
A5=Not enough | B5=Cosmetic UI polish, bug fixes alone where the bounty asks for substantive work, repackaging an old demo, or presenting old functionality as newly built.
A6=Evidence to prepare | B6=Dated pre-event commit or prior submission link; commit history throughout event; changelog with dated work; README section separating old work from new work; short demo focused on the new functionality; sponsor-specific transaction/request IDs.
A7=Disclosure | B7=ETHGlobal rules say pre-existing work must be disclosed in writing and included in the submission. All new extension work must remain open source for Continuity submissions.
A8=Classic vs Continuity | B8=Classic/from-scratch track requires project-specific code/design/assets to begin when hacking officially starts. If not in an approved Continuity track, pre-existing project-specific work can make partner-prize/finalist submissions ineligible.
A9=Sponsor-specific caveat | B9=Check each bounty. Continuity eligibility differs by sponsor; some sponsors have a dedicated continuity bounty, others do not. Do not assume a continuity project can enter every track.
A10=Risk | B10=Undisclosed pre-existing work or misrepresenting what was built during the event can lead to disqualification, prize revocation or a ban from future events.
A11=Official source | B11=https://ethglobal.com/rules
